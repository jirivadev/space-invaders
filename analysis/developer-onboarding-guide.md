# Developer Onboarding Guide — Space Invaders

> Phase 3 deliverable. Date: 2026-07-31
> Practical guide for working with this codebase.

## 1. Setup

```bash
git clone <repo> && cd space-invaders
npm install          # Node 18+ recommended
npm run dev          # Vite dev server → http://localhost:5173
npm run build        # tsc typecheck + vite build → dist/index.html (single file)
npm run preview      # serve the production build
npm test             # vitest run — 244 tests / 13 files
npx vitest           # watch mode
```

**Note on pre-commit**: Husky runs `lint-staged`, which formats staged files and runs related Vitest tests for staged TypeScript files. Run `npm test` for the full suite.

## 2. Mental Model (5 bullets)

1. **One mutable `GameState`** — systems mutate it in place; no immutability. Read `types.ts` first.
2. **Systems, not components** — behavior lives in classes/functions under `src/game/system/` that read/write `GameState`. Each has one responsibility.
3. **Canvas-only gameplay** — React never touches game state. The engine pushes a diffed `UIState` via `onUIChange`; DOM components are a thin decorative shell.
4. **Pure math where possible** — animation/timing math lives in `rendering-math.ts` / `geometry.ts` (canvas-free, unit-tested). Keep new math there.
5. **Everything is tunable in one place** — `config.ts` (`GAME_CONFIG`, `COLORS`, `SPRITES`). No magic numbers in systems.

## 4. How to Add a New Feature (recipe)

Example: _add a new alien type._

1. **Config** — add `"hover"` to `Alien["type"]` union (`types.ts`), add `hover: 25` to `ALIEN_POINTS` (`config.ts`), add `SPRITES.hover` + `SPRITES_2.hover` (equal-width rows!).
2. **Factory** — add it to `rowTypes` in `createAliens` (`entity-factory.ts`).
3. **Logic** — collision already handles any `Alien.type` generically (points lookup + colors) — add specific behavior in the relevant system if needed.
4. **Rendering** — `RenderingSystem.drawAliens` looks up `COLORS[a.type]` and the sprite grid — add `hover` to `COLORS`.
5. **Test** — extend `entity-factory.test.ts` / `collision-system.test.ts`; add a focused describe block. Run `npx vitest <file>`.
6. Verify: `npm run build` + `npm test`.

## 5. Working with Levels & Formations

- Level 1-4 are hand-authored in `getLevelConfig` (`level-system.ts:7`); levels 5+ are formulaic: formations cycle `["grid","staggered","diamond","compact","wide"]`, speed caps at 4×, shoot interval floors at 0.4, bullet speed caps at 12, startY caps at 200.
- Formations are generated by `createFormationGrid` (`entity-factory.ts:14`) — a shared grid builder parameterized by rows, per-row column counts (number or function), spacing, row start x, and per-row offset. To add a formation: add a `case` in `createAliens` and a matching `FormationType` if new.
- Alien movement speed adapts to how many aliens remain: `getAlienStepInterval` (`level-system.ts:78`) — fewer aliens → faster steps (factor capped at 8×).

## 6. Testing Conventions

- **Location**: colocated `*.test.ts` beside sources (13 files, 244 tests).
- **Patterns** (see `engine.test.ts` for the canonical setup):
  - `localStorage` → `vi.stubGlobal("localStorage", {...})` with an in-memory store; `vi.unstubAllGlobals()` in `afterEach`.
  - Game loop → stub `requestAnimationFrame`/`cancelAnimationFrame`, capture the callback, invoke `_frame()` manually.
  - Canvas → stub `window` + a minimal mock 2D context (`fillRect`, `measureText`, etc. as `vi.fn()`).
  - State → `createMockState({...})` / `makeBullet()` etc. from `src/game/test-utils/factory.ts`.
- **Run one file**: `npx vitest src/game/system/level-system.test.ts`. Watch: `npx vitest`.
- **Coverage**: T-8 rendering-system, ui-rendering, ControlsHint, and PowerUpBanner tests are covered directly; add focused tests for new branches as needed.

## 7. Common Gotchas

- **`verbatimModuleSyntax` is on** — type-only imports must use `import type { ... }`. Runtime imports of types fail the build.
- **Sprite rows must be equal width** — uneven rows silently misrender (no error). There's a test for `SPRITES.player` only.
- **`swapRemove` reorders arrays** — never rely on element order after removal; don't keep stale references to removed entities (this is the root of T-2).
- **Alien caches are refreshed per frame** (`refreshAlienCaches`) — if you mutate `aliens` mid-frame, `aliveAliens`/`activeAliens` are stale until the next refresh. `checkLevelComplete` waits for active death animations before replacing a formation.
- **Injected frame time** — the engine computes `now` once per update and threads it through gameplay timing paths, so tests can inject deterministic timestamps (T-7).
- **StrictMode double-mounts effects in dev** — the `App.tsx` effect is written correctly (create + `start()`, cleanup + `stop()`); if you add `window` listeners anywhere, bind handler references once in the constructor so add/removeEventListener match.
- **Single-file build** — `vite-plugin-singlefile` inlines everything; `cssCodeSplit: false`. No code-splitting, no external assets in prod.
- **Tailwind v4** — no `tailwind.config`; styles come from `@import "tailwindcss"` in `index.css`. Add utilities inline, not via config.

## 8. Debugging Tips

- **Runtime errors**: `main.tsx` installs global `window.onerror` + `onunhandledrejection` and an `ErrorBoundary` — all log via `console.error`. The game loop itself is wrapped in try/catch (`engine.ts:102-108`).
- **Where to breakpoint**: `engine._update()` (step through the pipeline), `handleBulletCollisions` (combat), `processDeathAnimations` (scoring), `_notifyUI` (React bridge).
- **State inspection**: pause execution and inspect `engine.g` (the mutable `GameState`) — all fields live there.
- **Tests as repro**: to reproduce a bug, write a test with `createMockState` + targeted `make*` factories — far faster than playing.
- No debug `console.log` leftovers exist (all current logging is `console.error`); keep it that way.

## 9. Quality Bar (before committing)

1. `npm run build` — zero type errors (strict mode).
2. `npm test` — all 244 pass; add tests for new/changed logic.
3. `npx prettier --write <files>` (this is what the pre-commit hook would do).
4. No dead code — remove anything your change orphans (imports, exports, files). There was a prior cleanup pass removing exactly this.
5. Magic numbers → `GAME_CONFIG`; new colors → `COLORS`; new math → `rendering-math.ts` as a pure `compute*` function.
6. Don't break the sprite equal-width rule; don't rely on array order after `swapRemove`.
